# Web business onboarding design

## Goal

Новый владелец создаёт бизнес на сайте без перехода в Telegram. Telegram подключается только после создания кабинета и остаётся дополнительным рабочим каналом.

## Flow

1. Все CTA «Подключить бизнес» ведут на `/register` в той же вкладке.
2. Регистрация запрашивает имя владельца, email, пароль, название бизнеса и основного филиала.
3. Одна database transaction создаёт `User`, `Business`, OWNER `Membership`, `Branch`, профиль владельца как первого `StaffMember` и стандартное расписание 09:00-18:00 по всем дням.
4. После автоматического входа пользователь попадает на `/dashboard/onboarding`.
5. Onboarding объясняет следующие реальные действия: добавить первую услугу, настроить карту DushanbeCity и при желании подключить клиентского Telegram-бота. Никакой шаг не отправляет пользователя в `@manclient_bot` без явного действия из кабинета.
6. `/start` в platform bot остаётся бизнесовым: непривязанный чат получает одну кнопку входа; привязка выполняется подписанной ссылкой из авторизованного кабинета.

## Safety and validation

- Email нормализуется в lowercase, пароль минимум 10 символов, имена обрезаются и ограничиваются по длине.
- Email и slug уникальны; конфликт возвращается как понятная ошибка без раскрытия чужого бизнеса.
- Пароль хешируется существующим `hashPassword`.
- Регистрация не принимает role или businessId от клиента.
- Сбой любого шага откатывает всю transaction.

## Verification

- Unit/render test доказывает отсутствие `t.me` в CTA.
- Integration test доказывает атомарное создание tenant graph и запрет дубля email.
- E2E проходит landing -> register -> authenticated onboarding и мобильную геометрию.
