# Обработка чеков DushanbeCity

## Что считается подтверждением

ManClient подтверждает запись по изображению чека, но не называет платёж банковски верифицированным. `isBankVerified` остаётся `false`, пока DushanbeCity не предоставит API, webhook или выписку.

Автоподтверждение происходит только когда одновременно совпали:

- успешный статус;
- сумма в дирамах;
- последние четыре цифры карты филиала;
- уникальный номер операции внутри бизнеса;
- время операции между созданием booking и окончанием 15-минутного hold.

OCR работает локально в два прохода: русский текст для статуса, English numeric model для даты, времени, операции, карты и суммы. Полный номер карты из OCR не сохраняется.

## Когда нужен ручной разбор

`NEEDS_ATTENTION` означает, что чек сохранён, но хотя бы одно поле не распознано или не совпало. Администратор проверяет private original и данные Payment:

1. Открывает чек только через авторизованный backoffice/storage access.
2. Сравнивает operation number, сумму, время и recipient suffix.
3. Проверяет, не использован ли operation number другой записью.
4. Связывается с клиентом, если изображение обрезано или нечитаемо.
5. Не запрашивает полный номер карты в чате.

Нельзя подтверждать чек только потому, что сумма похожа. Нельзя менять `isBankVerified` вручную.

## Спор и хранение

AuditEvent сохраняет получение чека и lifecycle booking без полного номера карты. Original хранится по private storage key. Доступ к bucket ограничивается production workload и уполномоченным оператором.

При споре экспортируются только конкретный чек, audit events записи и Payment metadata. Экспорт регистрируется отдельно операционным процессом. Срок хранения и удаление должны быть согласованы до production pilot с учётом местных требований к персональным данным.
